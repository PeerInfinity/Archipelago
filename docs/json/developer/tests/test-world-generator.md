# World Generator Test

[← Back to Test Results Summary](../test-results/test-results-summary.md)

## Overview

The World Generator Test validates the **round-trip capability** of the export and world generation system. It tests whether a game's logic can be:

1. **Exported** from the original Python world to JSON rules
2. **Regenerated** as a new Python world from those JSON rules
3. **Re-exported** to JSON rules that match the original

This test is critical for ensuring that the world generator produces worlds with equivalent game logic to the originals.

## The Round-Trip Process

```
┌─────────────────────────┐
│  Original Python World  │  (e.g., worlds/tunic/)
└───────────┬─────────────┘
            │
            ▼ [Exporter]
┌─────────────────────────┐
│   Original rules.json   │  Exported game logic
└───────────┬─────────────┘
            │
            ▼ [World Generator]
┌─────────────────────────┐
│  WorldGen Python World  │  (e.g., worlds/tunic_worldgen/)
└───────────┬─────────────┘
            │
            ▼ [Exporter]
┌─────────────────────────┐
│   WorldGen rules.json   │  Re-exported game logic
└─────────────────────────┘
```

If the round-trip is successful, both `rules.json` files should be functionally equivalent, meaning the WorldGen world has the same game logic as the original.

## Test Stages

The test runs in 7 stages, divided into two groups:

### Prerequisite Tests (Original World)

| Stage | Name | Description |
|-------|------|-------------|
| 1 | **Original Gen** | Generate a seed using the original Python world |
| 2 | **Original Spoiler** | Run spoiler test on the original world to verify it works |

These must pass before WorldGen testing can proceed. If the original world doesn't work, there's no point testing the WorldGen version.

### World Generator Tests

| Stage | Name | Description |
|-------|------|-------------|
| 3 | **World Gen** | Create `_worldgen` Python world from `rules.json` |
| 4 | **Seed Gen** | Generate a seed using the `_worldgen` world |
| 5 | **Rules Comp** | Compare original `rules.json` with WorldGen `rules.json` |
| 6 | **WorldGen Spoiler** | Run spoiler test on the WorldGen world |
| 7 | **Cross-Validation** | Test original sphere log against WorldGen rules |

### What Each Stage Validates

**Stage 3 (World Gen)**: The world generator can parse the JSON rules and produce valid Python code. Checks that `__init__.py`, `Items.py`, `Locations.py`, `Regions.py`, `Rules.py`, and `Options.py` are created.

**Stage 4 (Seed Gen)**: The generated Python world is syntactically and semantically valid. Archipelago can load it and generate a working seed.

**Stage 5 (Rules Comp)**: The re-exported rules match the original. This is the strictest test - it verifies that no game logic was lost during the round-trip.

**Stage 6 (WorldGen Spoiler)**: The WorldGen world produces a completable game. The sphere log generated by the WorldGen world validates against its own rules.

**Stage 7 (Cross-Validation)**: The WorldGen world has equivalent logic to the original. This tests whether the **original** sphere log (which shows the correct order to collect items) validates against the **WorldGen** rules. If it passes, the WorldGen rules allow the same progression as the original.

## Test Modes

The test runs in two modes to test different aspects:

### Canonical Mode

```bash
python scripts/test/test-world-generator.py --canonical-seed
```

Uses the `--canonical-seed` flag, which places items in their **original locations** when seed is 1. This creates identical item placements between the original and WorldGen worlds.

**Expected Results:**
- All stages should pass
- Rules Comparison passes (identical placements)
- Cross-Validation passes (identical sphere logs)

### Random Mode

```bash
python scripts/test/test-world-generator.py
```

Uses standard randomized item placement. The original and WorldGen worlds will have **different** item placements.

**Expected Results:**
- Stages 1-4 and 6 should pass
- **Rules Comparison fails** (expected - different item placements produce different location data)
- **Cross-Validation may fail** (different placements may require different progression)

The Random mode failures are **expected behavior**, not bugs. They occur because:
- Different seeds produce different item placements
- The `rules.json` includes placement data, which differs
- The sphere log is specific to the item placement

## Understanding the Results

### Reading the Results Table

| Column | Meaning |
|--------|---------|
| ✅ | Test passed |
| ❌ | Test failed |
| `-` | Skipped (earlier stage failed) |
| `Error` | An error occurred during the test |

### Why Canonical Mode Matters

Canonical mode is the **primary validation** that the world generator works correctly. When items are placed identically:

1. The rules.json files should be identical
2. The sphere logs should be identical
3. Cross-validation should always pass

If canonical mode fails, it indicates a real bug in the world generator.

### Why Random Mode Matters

Random mode tests that the WorldGen world is a **functional randomizer**, even though the comparison tests will fail due to different placements.

- Stage 6 (WorldGen Spoiler) is the key test - it proves the WorldGen world generates completable games
- Stages 3-4 prove the world can be loaded and used

## Running the Test

### Full Test (All Phases)

```bash
python scripts/test/test-world-generator.py --seed 1 --canonical-seed
```

### Test Specific Games

```bash
python scripts/test/test-world-generator.py --include-list "TUNIC.yaml" "Adventure.yaml"
```

### Skip Certain Phases

```bash
# Skip spoiler tests (faster, for testing world generation only)
python scripts/test/test-world-generator.py --skip-spoiler-test

# Skip cleanup (keep _worldgen worlds for inspection)
python scripts/test/test-world-generator.py --skip-cleanup
```

### Run Specific Phase Only

```bash
# Just setup (cleanup and regenerate templates)
python scripts/test/test-world-generator.py --phase setup

# Just generate original seeds and create worldgen worlds
python scripts/test/test-world-generator.py --phase generate-test-worlds

# Just run the spoiler tests
python scripts/test/test-world-generator.py --phase test
```

## Common Issues

### Rules Comparison Fails in Random Mode

**This is expected.** Random mode produces different item placements, so the rules.json files will differ in:
- `canonical_placements` section
- `locked` flags on locations
- Item placement data

Use `--ignore-canonical` with the comparison script to focus on structural differences only.

### Cross-Validation Fails

This means the original sphere log doesn't validate against the WorldGen rules. Possible causes:

1. **Different item placements** (expected in random mode)
2. **Missing or incorrect rules** in the WorldGen world
3. **Helper function expansion issues** in the world generator

In canonical mode, this indicates a bug in the world generator.

### World Generation Fails

The world generator couldn't create valid Python code. Check:
- The source `rules.json` is valid
- All helper functions are properly expanded
- Complex rule patterns are supported
