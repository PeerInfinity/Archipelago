# Spoiler Tests

[← Back to Test Results: Minimal](../test-results/test-results-spoilers-minimal.md) | [Full](../test-results/test-results-spoilers-full.md)

## Overview

The Spoiler Tests validate that Archipelago game worlds are completable by simulating sphere-by-sphere progression through the game. They verify that the frontend's Rule Builder engine correctly evaluates game logic and produces the same accessibility results as the Python backend.

There are two variants of the spoiler test:

| Test | What It Validates | Use Case |
|------|-------------------|----------|
| **Minimal Spoiler Test** | Advancement items only (items required to beat the game) | Quick validation of core progression logic |
| **Full Spoiler Test** | All locations (including optional content) | Thorough verification of complete game logic |

## What The Tests Verify

1. **World generation succeeds**: The game world can be generated without errors using `Generate.py`
2. **Rules are valid**: The exported JSON rules file correctly represents the game's logic
3. **Game is completable**: All tested locations can be reached in a valid order (sphere progression)
4. **Logic is consistent**: The frontend's Rule Builder engine produces the same accessibility results as the sphere log generated by the Python backend

## Test Flow

```
┌─────────────────────────────────────────────────────────────────────┐
│                        Test Orchestration                            │
│                   (test-all-templates.py)                           │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│  1. Configure host.yaml for spoiler mode                            │
│     Minimal: extend_sphere_log_to_all_locations: false              │
│     Full:    extend_sphere_log_to_all_locations: true               │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│  2. Generate world (Generate.py)                                    │
│     - Creates randomized item placement                             │
│     - Exports rules JSON (game logic for frontend)                  │
│     - Exports sphere log (expected progression order)               │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│  3. Run Playwright test (npm test --mode=test-spoilers)             │
│     - Opens frontend in test mode                                   │
│     - Frontend loads rules JSON and sphere log                      │
│     - Simulates collecting items sphere-by-sphere                   │
│     - Validates accessible locations match expected                 │
└─────────────────────────────────────────────────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────────────┐
│  4. Record results                                                  │
│     - Pass/fail status                                              │
│     - Sphere reached before failure (if any)                        │
│     - Error details for debugging                                   │
└─────────────────────────────────────────────────────────────────────┘
```

## Minimal vs Full Spoiler Tests

| Aspect | Minimal Spoiler Test | Full Spoiler Test |
|--------|---------------------|-------------------|
| **Locations tested** | Advancement items only | All locations |
| **Configuration** | `extend_sphere_log_to_all_locations: false` | `extend_sphere_log_to_all_locations: true` |
| **Speed** | Faster | Slower |
| **Coverage** | Core progression logic | Complete game logic |
| **Use case** | Quick validation, CI checks | Thorough verification |
| **Runs after** | Setup | Minimal spoiler test |

The minimal test focuses on items required to complete the game. The full test also validates optional locations, ensuring all game content is reachable with the correct logic.

## Understanding the Results Table

### Result Columns

| Column | Description |
|--------|-------------|
| **Game Name** | Display name from the game's template YAML file |
| **Test Result** | Pass/fail status with seed information (e.g., "Passed seeds 1-10") |
| **Gen Errors** | Number of errors during world generation (must be 0 to pass) |
| **Sphere Reached** | Highest sphere number successfully validated (fractional = partial sphere) |
| **Max Spheres** | Total spheres in the game (varies by game complexity and settings) |
| **Progress** | Percentage of spheres completed (🟢 Complete, 🟡 Partial, 🔴 Failed) |
| **Exporter** | ✅ = generic exporter, file size = custom Python exporter |
| **GameLogic** | ✅ = generic logic, file size = custom JavaScript logic |

### Pass Criteria

A test passes when:
- Generation completes without errors (`error_count = 0`)
- At least one sphere exists (`max_spheres > 0`)
- All spheres are successfully processed to completion

## Custom Exporters and Game Logic

The **Exporter** and **GameLogic** columns indicate whether a game uses custom components or the generic systems. For detailed information, see [Custom Exporters and Game Logic](./custom-exporters-and-logic.md).

## GitHub Actions Workflow

The tests run in the `test-all-sequential.yml` workflow:

1. **Setup**: Creates/updates the `test-results-update` branch
2. **Minimal spoiler test**: 10 parallel jobs test all templates
3. **Combine minimal results**: Merge artifacts into single results file
4. **Full spoiler test**: 10 parallel jobs test all templates (runs after minimal)
5. **Combine full results**: Merge artifacts into single results file
6. **Generate documentation**: Update markdown charts
7. **Commit**: Push results to `test-results-update` branch

### Workflow Options

| Option | Description | Default |
|--------|-------------|---------|
| `spoiler_mode` | `single-seed` or `10-seeds` | `10-seeds` |
| `start_seed` | Starting seed number | 1 |
| `spoiler_tests` | `skip`, `minimal-only`, `full-only`, `both` | `both` |
| `retest_failures` | Retry failed tests 1-3 times | `2-times` |
| `template_type` | `original`, `worldgen`, or `apworld` | `original` |

## Running Locally

### Quick Test (Single Game, Single Seed)

```bash
source .venv/bin/activate

# Minimal spoiler test
python scripts/setup/update_host_settings.py minimal-spoilers
python Generate.py --weights_file_path "Templates/Adventure.yaml" --multi 1 --seed 1
npm test -- --mode=test-spoilers --game=adventure --seed=1

# Full spoiler test
python scripts/setup/update_host_settings.py full-spoilers
python Generate.py --weights_file_path "Templates/Adventure.yaml" --multi 1 --seed 1
npm test -- --mode=test-spoilers --game=adventure --seed=1
```

### Full Test Suite

```bash
source .venv/bin/activate

# Run minimal spoiler tests for all games
python scripts/test/test-all-templates.py --minimal-spoilers -p

# Run full spoiler tests for all games
python scripts/test/test-all-templates.py --full-spoilers -p
```

### Test Specific Games

```bash
python scripts/test/test-all-templates.py --include-list "Adventure.yaml" "TUNIC.yaml" --minimal-spoilers -p
```

### Test Multiple Seeds

```bash
python scripts/test/test-all-templates.py --seed-range 1-10 --minimal-spoilers -p
```

## Interpreting Failures

| Failure Type | Meaning | Debugging Steps |
|--------------|---------|-----------------|
| **Gen Errors > 0** | World generation failed | Check `generate_output.txt` for Python errors |
| **Sphere 0** | No locations accessible at start | Verify start region and initial items in rules JSON |
| **Partial spheres** | Logic error mid-game | Compare sphere log events with frontend state |
| **Intermittent** | Passes on retry | Possible race condition or non-deterministic logic |

### Common Causes of Failures

1. **Custom exporter bug**: The exporter isn't correctly translating Python rules to JSON
2. **Missing game logic**: Complex rules need custom JavaScript that hasn't been implemented
3. **Rule Builder limitation**: The generic Rule Builder can't express certain logic patterns
4. **World definition issue**: The underlying Archipelago world has a bug
