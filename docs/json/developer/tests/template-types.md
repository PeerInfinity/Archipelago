# Template Types

[← Back to Test Results Summary](../test-results/test-results-summary.md)

## Overview

The test suite runs against three different types of game templates. Each type uses the same test methodology but validates different aspects of the system.

| Template Type | Source | Purpose |
|---------------|--------|---------|
| **Original** | Archipelago Python worlds | Validates the exporter and frontend work correctly with official game logic |
| **WorldGen** | Regenerated from JSON rules | Validates the world generator produces working worlds |
| **APWorld** | Community `.apworld` files | Validates compatibility with community-created games |

## Original Templates

**Test Results:** [Summary](../test-results/test-results-summary.md) | [Spoilers](../test-results/test-results-spoilers-minimal.md) | [Multiclient](../test-results/test-results-multiclient.md) | [Multiworld](../test-results/test-results-multiworld.md)

Original templates use the standard Archipelago world definitions written in Python. These are the "source of truth" for each game's logic.

### Characteristics

- **Location:** `worlds/{game}/` (Python packages)
- **Template files:** `Players/Templates/{Game Name}.yaml`
- **Maintained by:** Archipelago developers and game maintainers
- **Logic defined in:** Python code

### What These Tests Validate

1. The **exporter** correctly converts Python game logic to JSON rules
2. The **frontend Rule Builder** correctly evaluates the exported rules
3. The **multiclient** communication works with the exported data
4. Games are **compatible** with each other in multiworld

### Example

```
World:     worlds/adventure/__init__.py (Python)
Template:  Players/Templates/Adventure.yaml
Export:    frontend/presets/adventure/AP_*/AP_*_rules.json
```

## WorldGen Templates

**Test Results:** [Summary](../test-results/test-results-summary-worldgen.md) | [Spoilers](../test-results/test-results-spoilers-minimal-worldgen.md) | [Multiclient](../test-results/test-results-multiclient-worldgen.md) | [Multiworld](../test-results/test-results-multiworld-worldgen.md)

WorldGen templates use worlds that have been regenerated from JSON rules files using the world generator. This tests the "round-trip" capability of the system.

### The Round-Trip Process

```
Original Python World
        ↓
    [Exporter]
        ↓
   JSON Rules File
        ↓
  [World Generator]
        ↓
Generated Python World (WorldGen)
        ↓
    [Exporter]
        ↓
   JSON Rules File
        ↓
   [Frontend Tests]
```

### Characteristics

- **Location:** `worlds/{game}_worldgen/` (generated Python packages)
- **Template files:** `Players/Templates/{Game Name} WorldGen.yaml`
- **Generated by:** `python -m world_generator`
- **Logic defined in:** Generated Python code using Rule Builder syntax

### What These Tests Validate

1. The **world generator** produces valid, working Python worlds
2. Generated worlds can be **exported back to JSON** correctly
3. The **round-trip** (export → generate → export) preserves game logic
4. Generated worlds work in **multiworld** with other games

### Why WorldGen Tests Matter

If a game passes original tests but fails WorldGen tests, it indicates:
- The world generator doesn't fully support some game feature
- Some game logic is lost during the export → generate cycle
- The Rule Builder syntax can't express some original Python logic

### Example

```
Original:  worlds/adventure/__init__.py
Export:    frontend/presets/adventure/AP_*/AP_*_rules.json
Generate:  python -m world_generator rules.json -o worlds/adventure_worldgen
WorldGen:  worlds/adventure_worldgen/__init__.py
Template:  Players/Templates/Adventure WorldGen.yaml
```

## APWorld Templates

**Test Results:** [Summary](../test-results/test-results-summary-apworld.md) | [Spoilers](../test-results/test-results-spoilers-minimal-apworld.md) | [Multiclient](../test-results/test-results-multiclient-apworld.md) | [Multiworld](../test-results/test-results-multiworld-apworld.md)

APWorld templates use community-created games distributed as `.apworld` archive files. These are not part of the core Archipelago distribution.

### Characteristics

- **Location:** `custom_worlds/{game}.apworld` (ZIP archives)
- **Template files:** `Players/Templates/{Game Name}.yaml` (generated after loading)
- **Maintained by:** Community developers
- **Logic defined in:** Python code within the archive

### What These Tests Validate

1. The **exporter** works with community-created worlds
2. Community worlds have **compatible** logic structures
3. APWorlds work in **multiworld** with official games
4. The system handles **external dependencies** correctly

### Why APWorld Tests Matter

APWorld tests help identify:
- Community games that need custom exporters
- Games with logic patterns the generic exporter doesn't handle
- Compatibility issues between community and official games

## Comparing Test Results

### Pass Rates

The three template types often have different pass rates:

| Type | Typical Pass Rate | Reason |
|------|-------------------|--------|
| **Original** | Highest (~100%) | Reference implementation, most mature |
| **WorldGen** | Lower (~80-90%) | Some games have logic the generator can't reproduce |
| **APWorld** | Variable | Depends on how games are structured |

## Running Tests for Each Type

### Original Templates (Default)

```bash
python scripts/test/test-all-templates.py -p
```

### WorldGen Templates

```bash
python scripts/test/test-all-templates.py --include-pattern "*WorldGen.yaml" -p
```

### APWorld Templates

```bash
python scripts/test/test-all-templates.py --custom-worlds-only -p
```

### All Types

```bash
# Run original, then worldgen, then apworld
python scripts/test/test-all-templates.py -p
python scripts/test/test-all-templates.py --include-pattern "*WorldGen.yaml" -p
python scripts/test/test-all-templates.py --custom-worlds-only -p
```
